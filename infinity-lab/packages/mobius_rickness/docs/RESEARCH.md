## Differential geometry of the Mobius strip: first/second fundamental forms and Gaussian curvature K=-1/(4E^2), its strict negativity as a ruled surface, finite-difference computation with failure modes, and the zero set of a weighted curvature K*R

For the standard Mobius parametrization x=(1+v cos(u/2))cos u, y=(1+v cos(u/2))sin u, z=v sin(u/2), the first fundamental form is remarkably simple: E=(1+v cos(u/2))^2+v^2/4, F=0, G=1 (orthogonal, arc-length in v). It is a ruled surface r(u,v)=alpha(u)+v*beta(u), so r_vv=0 and thus N=0; the mixed coefficient reduces exactly to M=-1/(2 sqrt(E)) (the triple product r_uv.(r_u x r_v)=-1/2). Hence the Gaussian curvature K=(LN-M^2)/(EG-F^2)=-M^2/E=-1/(4E^2). Because M never vanishes, K<0 STRICTLY on the whole open strip (|v|<1) — the general ruled-surface bound K<=0 (from N=0) is here strict everywhere. I verified E,F,G,M,N and K=-1/(4E^2) numerically to ~6e-8 in pure stdlib Python. Numerically, K is rebuilt from central-difference partials, which trades O(h^2) truncation against O(eps/h^2) cancellation round-off (optimal h~1e-5 for first, ~1e-4 for second derivatives); boundaries need one-sided stencils and the u-direction needs the Mobius gluing r(2pi,v)=r(0,-v) (v->-v across the seam). Complex-step differentiation via cmath gives cancellation-free first derivatives since cos/sin are entire. Finally, since K is nowhere zero, the weighted curvature K*R has Zero(K*R)=R^{-1}(0): a strictly positive weight R>0 gives no zeros at all, while a sign-changing R makes the zero locus exactly the level curve R=0 — a finite bounding curve inside the parameter domain, echoing the Central-Finite-Curve idea of a boundary partitioning a space, and Gojo's Infinity as an asymptotic barrier that (like K) is 'always there,' never reaching zero."


**Key concepts**

- The standard Mobius parametrization is a RULED surface r(u,v)=alpha(u)+v*beta(u) with alpha the unit center circle and beta a unit director rotating at half rate (the half-twist).
- Orthogonal, arc-length-in-v parametrization: F=0 and G=1 exactly; the whole metric is carried by E=(1+v cos(u/2))^2+v^2/4.
- EG-F^2 = E = |r_u x r_v|^2 > 0 for |v|<1, so the surface is regular and orientation-normal is locally (never globally) defined.
- r_vv=0 (straight rulings) forces N=0, giving the universal ruled-surface bound K=-M^2/(EG-F^2) <= 0.
- The scalar triple product r_uv.(r_u x r_v) collapses to exactly -1/2, so M=-1/(2 sqrt(E)) is NOWHERE zero => K<0 STRICTLY everywhere.
- Closed form K=-1/(4E^2); no eigen/linear-algebra needed once F=0,G=1,N=0 are established.
- Finite-difference curvature must trade truncation O(h^2) against cancellation round-off O(eps/h^2); optimal h differs for first (~1e-5) and second (~1e-4) derivatives.
- Complex-step differentiation gives cancellation-free first derivatives because cos/sin are entire; useless if the surface uses abs/max/branch cuts.
- Non-orientability shows up numerically as the gluing r(2pi,v)=r(0,-v): periodic stencils must flip v->-v across the seam.
- Because K is nowhere zero, Zero(K*R)=R^{-1}(0): a positive weight yields NO zeros, a sign-changing weight makes the zero set exactly the level curve R=0.

**Algorithms**

- **Analytic curvature evaluation (closed form)** — Because F=0 and G=1 and the second-form coefficients collapse (N=0, M=-1/(2 sqrt(E))), the whole curvature reduces to a single scalar formula K(u,v) = -1/(4E(u,v)^2) with E(u,v)=(1+v cos(u/2))^2 + v^2/4. Implement `E(u,v)` and `K(u,v)` directly; no linear algebra, no differencing, no division that can blow up (E is bounded below by (1-|v|)^2+v^2/4>0 for |v|<1). This is the ground-truth oracle used to validate every numerical path.
  - _Method:_ Direct evaluation with math.cos; K=-1/(4*E*E). Exact to machine precision.
  - _Pitfalls:_ If the half-width w>=1 then 1+v cos(u/2) can hit 0 and E->v^2/4 is still >0, but the strip self-intersects and is no longer embedded/regular — validate w<1 at the boundary. Guard against E==0 only defensively.
- **Finite-difference curvature (central stencils)** — General-purpose path that treats surf(u,v) as a black box and rebuilds E,F,G,L,M,N,K from difference quotients, then K=(LN-M^2)/(EG-F^2). Used when the surface is swapped for a non-analytic one, or to cross-check the closed form. Verified against the oracle: max |K_num-K_analytic| ~ 6e-8 over 20000 random points at h=1e-4.
  - _Method:_ Central differences: r_u=(f(u+h,v)-f(u-h,v))/(2h) [O(h^2)]; r_uu=(f(u+h,v)-2f(u,v)+f(u-h,v))/h^2 [O(h^2)]; mixed r_uv=(f(u+h,v+k)-f(u+h,v-k)-f(u-h,v+k)+f(u-h,v-k))/(4hk) [O(h^2+k^2)]. Normal n=(r_u x r_v)/sqrt(EG-F^2); L,M,N are dots of the second derivatives with n.
  - _Pitfalls:_ Step-size trade-off: truncation ~O(h^2) shrinks as h->0 but round-off from catastrophic cancellation grows ~eps*|f|/h (first deriv) and ~4*eps*|f|/h^2 (second deriv). Optimal h ~ (3 eps)^{1/3} ~ 1e-5 for first derivatives and ~ (48 eps)^{1/4} ~ 1e-4 for second derivatives (eps=2.22e-16). Using one h for both is a compromise; 1e-4 was best here. The second-difference numerator subtracts near-equal O(1) values to get an O(h^2) result, so relative error ~ eps/h^2 — never push h below ~1e-6.
- **Complex-step first derivatives (cancellation-free)** — The surface is a composition of cos/sin, hence entire (holomorphic), so first partials can be taken by the complex-step trick with NO subtractive cancellation. r_u = Im(surf(u+i*h, v))/h, error O(h^2) but with h as small as 1e-200 so truncation is effectively zero and there is no round-off. Verified to match central differences to 10 digits. Gives a rock-solid first fundamental form (E,F,G) and normal direction.
  - _Method:_ Use cmath (stdlib): evaluate surf with u replaced by complex(u,h); take .imag/h componentwise. h=1e-200.
  - _Pitfalls:_ Requires the map to be analytic in the perturbed variable — true for cos/sin/polynomials, FALSE if the surface contains abs(), max(), branch cuts (sqrt of possibly-negative, etc.), which silently corrupt the imaginary part. Does not directly give second derivatives (L,M,N) — you must combine complex-step with one real difference (complex-step-on-a-difference) or use multicomplex numbers; plain complex-step alone cannot produce r_uu.
- **Boundary and Mobius-periodic stencil handling** — Central stencils need neighbors on both sides. In v the domain is [-w,w]: at v=+-w use 3-point one-sided differences (still O(h^2)) instead of central. In u the domain is periodic BUT with the Mobius twist: r(2*pi, v) = r(0, -v) (verified numerically: r(2pi,0.4)=r(0,-0.4)=(0.6,0,0)). So a wrap-around neighbor at u<0 or u>2pi must be fetched as (u mod 2pi) with v -> -v when an odd number of 2pi wraps occurred. Ignoring the v->-v flip produces a spurious seam of large curvature error along u=0.
  - _Method:_ Index map: given (u,v), reduce k=floor(u/(2pi)); u'=u-2pi*k; v'=v if k even else -v. Sample surf(u',v'). Switch to forward/backward 3-point stencils within one step of the v-boundary.
  - _Pitfalls:_ Forgetting the twist (treating u as ordinary periodic) breaks non-orientability and gives wrong r_u across the seam. One-sided differences at the boundary drop an order if only 2-point; use the 3-point one-sided form to keep O(h^2).
- **Zero-set extraction of K*R** — Since K<0 everywhere (never 0), Zero(K*R)=Zero(R). For R>0 the zero set is empty (report no contour). For sign-changing R, extract R^{-1}(0) as a curve in the (u,v) domain. Implement with marching-squares over a grid: detect sign changes of R on cell edges and locate the crossing by bisection (stdlib only). K plays no role in the location of zeros, only in confirming they coincide exactly with R's zeros.
  - _Method:_ Sample R on a (u,v) grid; for each edge with a sign change, bisect R to a tolerance; connect segments per marching-squares case table. Optionally weight/annotate each contour point with K*R gradient magnitude.
  - _Pitfalls:_ Grid too coarse misses closed loops or thin sign-change bands of R; tangential (double) zeros where R touches 0 without crossing are invisible to sign-change detection — need a |R|<tol fallback. Do NOT divide by K or by (K*R) anywhere; and do not attribute any zero to K, which is provably nonvanishing.

## Tracing the zero-set curve R(u,v)=0 of a scalar field on the 2D Mobius parameter domain and lifting it to 3D: scan-line bisection root finding, marching squares, and predictor-corrector continuation

**Key concepts**

- Zero set / level set: tracing {(u,v) in D : R(u,v)=0} = R^{-1}(0), the Central Finite Curve realized as the zero-set of the Rickness field R on the Mobius parameter domain
- Bolzano / Intermediate Value Theorem: a sign change g(a)*g(b)<0 of a continuous g certifies at least one (odd count of) root in (a,b) — the only rigorous existence guarantee behind scan-line bracketing
- Bisection interval-halving convergence: error (b-a)/2^n — literally the convergent geometric series 1/2+1/4+1/8+... = 1, the same Zeno/infinite-subdivision structure used to model Gojo's Infinity (approach halves forever, barrier never crossed)
- Implicit Function Theorem: where grad R != 0 (0 is a regular value), R^{-1}(0) is a smooth embedded 1-manifold with tangent T perpendicular to grad R — the licence for smooth curve tracing
- Marching squares 16-case lookup + bilinear/asymptotic saddle decider for globally consistent, topologically closed contour extraction
- Linear edge interpolation t = F_A/(F_A-F_B): zero of the edge's linear interpolant, O(h^2) accurate
- Predictor-corrector (pseudo-arclength) continuation: Euler tangent predictor + minimal-norm Newton corrector for uniform arc-length sampling and natural closed-loop traversal
- Minimal-norm (Gauss-Newton) correction for one equation in two unknowns: step along grad R, x <- x - R*grad R/||grad R||^2
- Regular vs singular points: grad R -> 0 marks tangencies, self-intersections and bifurcations where bracketing misses roots and continuation breaks down
- Robustness/accuracy tradeoff: grid density h controls which features are found (topology), tolerance eps and step ds control positional accuracy — decouple them via a hybrid pipeline
- Hybrid strategy: marching squares (find all components + seeds) -> stitch -> continuation/Newton (polish to high accuracy) = best coverage and accuracy
- Mobius non-orientable seam identification (2pi, v) ~ (0, -v): tracing must wrap u and flip v; R must satisfy R(0,-v)=R(2pi,v) to be single-valued on the band
- 3D lift r(u,v) = ((1+v cos(u/2))cos u, (1+v cos(u/2))sin u, v sin(u/2)): mapping the parameter-space zero curve onto the physical Mobius strip

**Algorithms**

- **Scan-line bisection root finding (1D IVT bracketing)** — Reduce the 2D problem to 1D families: fix one parameter (e.g. hold u = u_i, sweep v), giving g(v) = R(u_i, v) on [V_MIN, V_MAX]. Sample g at N+1 nodes v_k = V_MIN + k*h, h = (V_MAX-V_MIN)/N. Wherever g(v_k)*g(v_{k+1}) < 0, Bolzano's theorem guarantees an odd number of roots in (v_k, v_{k+1}); refine each such bracket with bisection to tolerance eps. This is exactly what the repo's curve.py find_roots_in_v already does (scan v per u-column, bisect each sign change to 1e-9). For full 2D coverage, scan BOTH families (rows and columns) so a nearly-horizontal or nearly-vertical curve segment is not missed by one sweep direction.
  - _Method:_ Sampling + Bolzano sign-change detection + bisection. Bracket [a,b] with g(a)*g(b)<0; iterate m=(a+b)/2, replace the endpoint whose sign matches g(m). Error after n steps: (b-a)/2^(n+1). To reach eps: n = ceil(log2((b-a)/eps)) iterations (e.g. domain width 1.0 to eps=1e-9 needs 30 steps). Guaranteed to converge for any continuous g given a valid bracket. Optionally upgrade the corrector to Brent's method (inverse-quadratic + secant + bisection fallback) for superlinear speed while retaining the bracket guarantee.
  - _Pitfalls:_ Even-multiplicity roots (tangencies where R touches 0 without crossing, ||grad R||->0) produce no sign change and are invisible to bracketing. Two roots inside one sampling cell (spacing < h) cancel and are missed -> the sampling density h is the true resolution limit, NOT the bisection tol. False roots appear at discontinuities/poles (sign flips there are not zeros) -> guard by checking |g| stays bounded, or only apply to fields known continuous. Floating point: g may never evaluate to exactly 0.0 and (b-a) cannot shrink below ~|b|*machine_eps (~2.2e-16), so set eps well above that. Endpoints are open-interval only; a root exactly at a sample node must be caught by an explicit g(v_k)==0 test (curve.py does this).
- **Marching squares (global contour topology)** — Evaluate F_ij = R(u_i, v_j) on a full grid. Classify each corner by sign(F) (inside F<0 / outside F>=0), giving each cell a 4-bit case index (2^4 = 16 cases). A static lookup table maps each case to the set of cell edges the contour crosses and how to connect them into segments. On every crossing edge, place the crossing point by linear interpolation of the zero of the edge's linear interpolant. Output is a soup of short line segments approximating R=0 over the whole domain at once. Best used as a topology/seed finder: it discovers every connected component (including closed loops) that crosses any cell edge, which the single-direction scan in curve.py can miss.
  - _Method:_ Per crossing edge from corner A (value F_A) to B (value F_B): t = F_A/(F_A - F_B), P = A + t*(B - A). Ambiguous saddle cases (indices 5 and 10: the two inside corners are diagonal) are resolved by the asymptotic/mean decider using the bilinear interpolant F(x,y)=F00(1-x)(1-y)+F10 x(1-y)+F01(1-x)y+F11 xy: compute the saddle value alpha = (F00*F11 - F10*F01)/(F00 + F11 - F10 - F01); if sign(alpha)==sign(F00) join one way, else the other. Position error of each vertex is O(h^2) times the local curvature of R (linear interpolant vs true zero). Consistent saddle resolution guarantees a topologically closed, non-self-crossing piecewise-linear approximation.
  - _Pitfalls:_ Features smaller than one cell vanish (a closed loop entirely inside a cell leaves no edge crossing) -> refine h or add adaptive subdivision where all 4 corners share a sign but the cell interior may dip. Ambiguous saddles resolved inconsistently create spurious crossings or gaps. Sharp corners of R=0 are rounded to O(h). Raw output is unordered segments; it does NOT give an arc-length-parametrized curve until you stitch shared endpoints (see stitching algorithm). Cost is O(N_u * N_v) evaluations regardless of how little of the domain contains the curve.
- **Predictor-corrector pseudo-arclength continuation (smooth tracing)** — The rigorous 'real curve' tracer. By the Implicit Function Theorem, wherever grad R = (R_u, R_v) != 0 (0 is a regular value), R^{-1}(0) is a smooth 1-manifold with a well-defined tangent. Given one seed point x0 on the curve (from a scan-line root or a marching-squares vertex, Newton-polished), walk along the curve in equal arc-length steps: PREDICT with an Euler step along the unit tangent, then CORRECT back onto the curve with Newton. This yields an ordered, densely and uniformly sampled polyline of arbitrary accuracy, and traverses closed loops naturally.
  - _Method:_ Tangent: the curve satisfies grad R . dx/ds = 0, so T = (R_v, -R_u)/||grad R|| (choose sign to preserve heading: flip if T_new . T_old < 0). Predictor (explicit Euler): x_pred = x_k + ds*T_k. Corrector (Gauss-Newton / minimal-norm Newton for the single equation R=0 in 2 unknowns): x_{m+1} = x_m - R(x_m) * grad R(x_m) / ||grad R(x_m)||^2, iterate until |R| < eps (quadratic convergence near a regular point). grad R by central differences: R_u=(R(u+dh,v)-R(u-dh,v))/(2dh). Closed-loop termination: after a minimum number of steps, stop when ||x_k - x0|| < ds. Adaptive step: shrink ds (e.g. halve) when the corrector needs too many iterations or the turning angle acos(T_k.T_{k-1}) exceeds a cap; grow it when convergence is easy.
  - _Pitfalls:_ Near singular points ||grad R||->0 (critical points, self-intersections, bifurcations) the tangent is undefined and Newton stalls or diverges (the corrector divides by ||grad R||^2) -> detect small ||grad R|| and stop/branch-switch; the IFT smoothness guarantee is void there. Step too large lets the Newton corrector snap onto a DIFFERENT nearby branch of the curve (branch-jump) -> cap the turning angle and/or corrector displacement. Fixed ds overshoots high-curvature regions -> adaptive step. Needs one seed per connected component; a loop with no seed is never traced -> harvest seeds from marching squares and dedupe components once traced. Euler predictor accumulates O(ds^2) drift per step (bounded by the corrector) — for higher order, use an RK2 predictor or include curvature.
- **Segment stitching and connected-component linking** — Convert unordered marching-squares segments (or per-column scan roots) into ordered polylines, one per connected component, so downstream code has a real parametrized curve. Also the mechanism to seed continuation exactly once per component.
  - _Method:_ Snap every vertex to a grid-hash of resolution ~h/4 so shared segment endpoints coincide, building an adjacency map endpoint -> incident segments. Walk: start at any degree-1 vertex (open arc) or any unused vertex (closed loop), repeatedly follow the unique unused incident segment until you return to the start (loop) or hit a dead end (arc boundary). Each maximal walk is one component. For continuation, take the first vertex of each walk as a seed and Newton-polish it to eps before tracing.
  - _Pitfalls:_ Floating-point endpoints don't compare equal -> must hash/snap with a tolerance tied to h, not exact equality. Saddle vertices have degree 4 (two curve branches meet) -> the walk order is ambiguous; resolve using the same asymptotic decider so branches pair consistently, otherwise components merge incorrectly. Choosing the hash cell too coarse fuses distinct nearby components; too fine fails to join genuine shared endpoints.
- **Mobius seam identification, multi-root columns, and 3D lift** — Handle the non-orientable domain and lift traced (u,v) points to the physical strip. The Mobius parameter rectangle [0,2pi] x [-0.5,0.5] is glued with a flip: from the repo embedding radial=1+v cos(u/2), z=v sin(u/2), the seam at u=0 gives point (1+v,0,0) and at u=2pi gives (1-v,0,0), which match iff v -> -v. So the identification is (2pi, v) ~ (0, -v). Any tracer crossing u=2pi must wrap u->u-2pi AND flip v->-v; a scan that stops at u=2pi without this leaves a false break in the curve. Multiple roots per column are all kept (a column can meet R=0 several times).
  - _Method:_ Well-definedness constraint: R must satisfy R(0, -v) = R(2pi, v) for the zero set to be a continuous curve on the band. Seam wrap for continuation: def wrap(u,v): while u>=2pi: u-=2pi; v=-v (and symmetric for u<0). Apply wrap after every predictor step and before the corrector; because grad R and the corrector are chart-local this composes correctly. Multi-root columns: collect ALL sign changes in each scan line (curve.py's loop already appends every crossing), do not stop at the first. 3D lift per (u,v): x=(1+v cos(u/2)) cos u, y=(1+v cos(u/2)) sin u, z=v sin(u/2) (repo mobius.surface). Optional lifted arc length = sum over segments of ||(dx,dy,dz)||, or integral of ||d/ds r(u(s),v(s))|| ds.
  - _Pitfalls:_ Forgetting the v-flip at the seam produces a curve that is C0-discontinuous at u=0/2pi or that closes onto the wrong endpoint — the classic Mobius orientation bug. Because the band is non-orientable, a globally consistent tangent ORIENTATION cannot always be chosen: a curve that wraps the strip once returns with reversed normal, so the T_new.T_old<0 heading test can spuriously flip after a seam crossing — special-case the sign convention across the seam. A curve pinned to a v-boundary (v=+/-0.5) is on the domain edge, not the interior, and grad-based continuation may push it out of [V_MIN,V_MAX] -> clamp/stop at boundaries. The repo's per-column scan returns points ordered by u but NOT stitched across the seam into a single loop; add wrap+stitching for a true closed Central Finite Curve.

## Torus differential geometry as the non-ruled surface with sign-changing Gaussian curvature

The ring torus is the canonical closed surface whose Gaussian curvature K changes sign, making it the geometric counterpart to the Mobius strip in this project. With the standard parametrization r(theta,phi) = ((R0 + r0 cos theta) cos phi, (R0 + r0 cos theta) sin phi, r0 sin theta), the first fundamental form is diagonal (E = r0^2, F = 0, G = (R0 + r0 cos theta)^2) and the second fundamental form gives the exact closed form K(theta) = cos(theta) / (r0 (R0 + r0 cos theta)). For a ring torus (R0 > r0 > 0) both r0 and the denominator factor R0 + r0 cos theta are strictly positive, so sign(K) = sign(cos theta): K > 0 on the outer half (-pi/2 < theta < pi/2, elliptic points), K < 0 on the inner half (pi/2 < theta < 3pi/2, hyperbolic/saddle points), and K = 0 exactly on the two circles theta = pi/2 and theta = 3pi/2 (the top and bottom circles at height z = +/-r0, radius R0). Because a ruled surface must have K <= 0 everywhere, the presence of K > 0 proves the torus is non-ruled. This gives a GENUINE, geometry-driven zero set for the weighted field K*R: on the torus K itself vanishes on those circles, so the boundary between positive-Rickness and negative-Rickness regions of K*R is pinned by curvature and persists even when the Rickness weight R stays strictly positive. This contrasts with the Mobius strip, where K < 0 everywhere forces the Central-Finite-Curve zero set to come entirely from R = 0. Numeric K from finite-difference fundamental forms matches the closed form to ~1e-8 (verified over 24 samples with h = 1e-4). The K=0 circles are located honestly by bisection, the Zeno-style halving that mirrors Gojo's Infinity.


**Key concepts**

- Ring torus parametrization by poloidal angle theta (tube) and toroidal angle phi (revolution) with major radius R0 and minor radius r0
- First fundamental form (metric): E = r0^2, F = 0, G = (R0 + r0 cos theta)^2 -- orthogonal coordinate net
- Second fundamental form: L = r0, M = 0, N = cos(theta)(R0 + r0 cos theta) for the outward unit normal
- Principal curvatures k1 = 1/r0 (poloidal, always positive) and k2 = cos(theta)/(R0 + r0 cos theta) (toroidal), curvature lines aligned with theta and phi
- Closed-form Gaussian curvature K = k1*k2 = cos(theta)/(r0 (R0 + r0 cos theta)); sign controlled solely by cos(theta) for a ring torus
- Point classification: elliptic (outer, K>0), hyperbolic/saddle (inner, K<0), parabolic (K=0) on theta = pi/2 and 3pi/2
- Non-ruled surface: a ruled surface has K <= 0 everywhere, so K>0 on the outer half proves the torus is not ruled -- unlike the cylinder (K=0) or one-sheet hyperboloid (K<0)
- Gauss-Bonnet consistency: the torus has Euler characteristic 0, so integral of K dA over the whole surface is exactly 0 -- outer-positive and inner-negative curvature cancel
- Geometry-driven zero curve: the zero set of K*R contains K^{-1}(0) = {theta=pi/2, 3pi/2} independent of R, so K*R vanishes there even when R>0
- Central Finite Curve analogy (Rick and Morty): a distinguished finite 1-D locus inside an otherwise unbounded/infinite space -- here realized as the curvature zero set
- Gojo Infinity analogy (Sabiq essay): a neutral/asymptotic boundary emerging from geometry itself (convergent bisection / Zeno halving) rather than from applied force -- mirrored by the bisection root finder
- Surface of revolution: K is independent of phi; every theta-slice reproduces the same curvature profile

**Algorithms**

- **Closed-form Gaussian curvature K(theta)** — Direct evaluation of K = cos(theta)/(r0*(R0 + r0*cos theta)). Implemented in torus.gaussian_curvature_closed. O(1), exact to machine precision. Used as the ground truth the numeric routine is validated against, and as the sign oracle for torus.sign_pattern and torus.zero_circles.
  - _Method:_ Analytic closed form; single division. Guard: if denom == 0.0 return 0.0.
  - _Pitfalls:_ The denom==0 guard silently masks a genuine singularity that occurs ONLY for non-ring tori (R0 <= r0), where R0 + r0 cos theta = 0 and k2 blows up -- returning 0.0 there is mathematically wrong (K is unbounded, not zero). For the ring torus (R0 > r0) the denominator is bounded below by r0*(R0 - r0) > 0 so this never triggers. Near theta = pi/2 the value is a small number formed from cos theta ~ (pi/2 - theta); it is accurate in absolute terms but has large relative error, so never divide by K near the zero circles.
- **Numeric Gaussian curvature via fundamental forms** — Surface-agnostic K for any r(a,b): central-difference the first/second partials r_u, r_v, r_uu, r_uv, r_vv, form E,F,G and the unit normal n = (r_u x r_v)/|r_u x r_v|, then L,M,N, and K = (L*N - M^2)/(E*G - F^2). Implemented in geometry.partials / geometry.fundamental_forms / geometry.gaussian_curvature and wrapped by torus.gaussian_curvature. Matches the closed form to ~1e-8 (verified).
  - _Method:_ Second-order central finite differences with step h. First derivatives O(h^2); pure second derivatives via (f(x+h)-2f(x)+f(x-h))/h^2; mixed partial via the 4-point stencil (pp - pm - mp + mm)/(4 h^2).
  - _Pitfalls:_ Step-size trade-off: second-derivative stencils divide by h^2, so round-off is amplified as eps/h^2 while truncation grows as h^2; the optimum h ~ eps^{1/4} ~ 1.2e-4 for doubles. The repo's _H = 1e-5 is on the small side (roundoff floor ~ eps/h^2 ~ 2e-6), so validate with tol ~1e-5..1e-6, not 1e-12 -- the numeric check above used h=1e-4 and got ~1.5e-8. Catastrophic cancellation: r_uu subtracts nearly equal points; keep h from getting too small. Denominator EG - F^2 -> 0 only at metric degeneracies (never for a ring torus); the denom==0 -> 0.0 guard again masks true singularities. Normal orientation flips sign of L,M,N but not K. Do not confuse this K's (u,v) with the closed form's theta -- the numeric torus K is phi-independent up to noise.
- **Zero-circle tracing by bisection (trace_torus_zero_circles)** — Locate theta where the closed-form K changes sign: sample K(theta) on a uniform grid over [0,2pi], detect sign changes prev_f*cur_f < 0, and refine each bracket with bisection to ~1e-9. Analytically returns pi/2 and 3pi/2. This is the honest, root-found zero curve -- no invented weighting.
  - _Method:_ Uniform sign-change scan followed by bisection (interval halving) to tolerance tol; requires a bracketing sign change f(lo)*f(hi) < 0.
  - _Pitfalls:_ Bisection needs a sign-straddling bracket and finds only simple (odd-order, transversal) zeros; the cos-theta zeros are simple so it works, but an even-order touch (curvature grazing zero) would be missed -- bisect raises ValueError if endpoints don't bracket, which is the correct fail-fast. Aliasing: too coarse a theta grid can hide two nearby roots in one cell; use enough samples (n_theta=400 default gives spacing ~0.0157, safe for two well-separated roots). The same machinery in curve.find_roots_in_v/bisect traces the Mobius R^{-1}(0); there the root exists only because R changes sign (K<0 everywhere), whereas on the torus the root exists because K changes sign -- the two cases are mathematically dual.
- **Grid evaluation of K, R, K_Rick** — Sample K, the Rickness weight R, and K_Rick = K*R over the parameter grid (field.evaluate_grid) for the ASCII heatmap and the +/- sign map. Establishes empirically that Mobius K<0 on the interior (field.assert_mobius_K_negative) and, for the torus analogue, that the K*R sign boundary tracks the K=0 circles.
  - _Method:_ Dense uniform sampling (nested lists; numpy import-guarded, pure-Python fallback). Sign map = sign of each cell; boundary inferred where neighboring signs differ.
  - _Pitfalls:_ Sign-map boundaries are only as sharp as the grid; the true K=0 curve should be pulled from the bisection tracer, not read off the raster. Floating noise near the zero circle can flip the raster sign of tiny K values -- threshold with a tolerance (|K| < tol => treat as 0) rather than testing == 0.0. Keep radii at the ring-torus default (R0=2, r0=1 here, or R0_DEFAULT=2, R_MINOR_DEFAULT=1) so the denominator stays positive and the sign map is meaningful.

## The Rick and Morty "Central Finite Curve" and its honest mathematical formalizations (level set vs. argmax ridge vs. Mobius orientation-reversing curve)

In-universe, the Central Finite Curve (CFC) is the Citadel-built enclosure around the sub-collection of the infinite multiverse consisting of exactly those realities where Rick Sanchez is the smartest being; outside it Rick is not the smartest. It is "infinite but finitely varying" — uncountably many universes, yet selected/bounded. Three honest formalizations map this onto real mathematics. (a) LEVEL/ZERO SET of a scalar "smartest-margin" field S(u)=I_Rick(u)-max_{x!=Rick} I_x(u): the CFC boundary is S^{-1}(0); by the regular-value (preimage) theorem this is a smooth codimension-1 submanifold — a genuine object, but a WALL (dim = dim M - 1), only a 1-D curve when the universe-parameter space is 2-D. This is what the mobius-rickness repo actually builds: on the Mobius strip (a ruled surface with Gaussian curvature K<0 strictly on the interior) the weighted field K_Rick = K*R vanishes iff the sign-changing Rickness R(u,v)=cos u + 0.4 v cos(u/2) + 0.2 sin u vanishes, so the CFC is EXACTLY R^{-1}(0), a real 1-D zero curve on the 2-D strip. (b) ARGMAX RIDGE / epsilon-band of a Rickness score over a manifold: the Eberly height-ridge (gradient parallel to the top Hessian eigenvector, all transverse Hessian eigenvalues negative) is a genuine 1-D object in ANY ambient dimension, traced by Subspace-Constrained Mean Shift (SCMS). Honest caveat: the literal argmax of a smooth field is generically isolated points (Morse theory), so "curve" requires the ridge definition, not a literal argmax; the epsilon-band {R*-R<=eps} is a shrinking tube around it. (c) MOBIUS / orientation-reversing curve: model the loop of universes as the core circle (v=0) of a Mobius band — the nontrivial R-line bundle over S^1 whose first Stiefel-Whitney class w_1!=0 and whose frame monodromy has determinant -1 — encoding that traversing the multiverse loop flips orientation ("smartest becomes dumbest"). Most defensible as a literal genuine 1-D curve: (b) the ridge, because it is intrinsically 1-D independent of ambient dimension and has decades of rigorous numerical backing (principal curves / density ridges). Most faithful to canon's "wall around realities": (a) the level set. Best for the Mobius-Rickness project: present the CFC as the ridge CORE curve (b), give that loop the Mobius bundle structure (c) to encode orientation reversal, and use the level set (a) as the transverse "wall" cross-section / boundary of the epsilon-band. The name "Central FINITE Curve" is then honestly earned: an object of finite 1-D Hausdorff measure (finite arc length L=integral|gamma'| dt) despite passing through uncountably many universes — the same taming-of-infinity motif as Gojo's Infinity in Sabiq's essay, where an infinite convergent geometric series (sum 2^{-n}=1) makes an unbounded process land on a finite value.


**Key concepts**

- Central Finite Curve (CFC): the Citadel's enclosure around exactly the realities where Rick is the smartest being; a curated, bounded selection from an infinite multiverse (fan-canon, Rick and Morty S6E1 'Solaricks').
- 'Infinite but finite' reconciled as finite measure on an infinite point-set: a 1-D curve of finite arc length through uncountably many universes — mirroring Gojo's convergent-series taming of infinity in the Sabiq essay.
- Smartest-margin scalar field S(u) = I_Rick(u) - max_{x!=Rick} I_x(u); CFC region = {S>0}, boundary/wall = {S=0}.
- Regular value theorem (preimage theorem): if 0 is a regular value of S then S^{-1}(0) is a smooth embedded submanifold of codimension 1 — hence a curve only when dim(M)=2.
- Sard's theorem: critical values have measure zero, so almost every threshold c gives a smooth (non-singular) level set; perturb c off critical values to guarantee regularity.
- Mobius strip is a RULED surface => Gaussian curvature K<=0, strictly K<0 on the interior (K=-1/4 on the center line v=0); the repo exploits this so K_Rick=K*R has the SAME zero set as R.
- Sign-changing weighting is essential: the naive positive weighting R_naive=1.5+... never crosses zero, so K_Rick had no honest zero set (a cop-out avoided by dropping the +1.5 constant).
- Eberly height-ridge: a point is on the 1-D ridge iff grad R is parallel to the leading Hessian eigenvector e_1 and the transverse Hessian eigenvalues lambda_2..lambda_n are all negative — intrinsically 1-D in any dimension.
- Argmax is generically 0-dimensional (Morse theory): isolated nondegenerate maxima; a 1-D max-set needs a symmetry/degeneracy, so use the ridge, not the literal argmax, for a curve.
- Epsilon-band B_eps={u: R*-R(u)<=eps}: a thick tube that collapses onto the ridge as eps->0; the level set {S=0} is its transverse boundary/cross-section.
- Non-orientability via first Stiefel-Whitney class w_1 in H^1(S^1;Z/2): w_1!=0 certifies the Mobius bundle; frame monodromy around the loop is a reflection (det=-1) = orientation reversal.
- Recommended synthesis for Mobius-Rickness: ridge core curve (genuine 1-D) + Mobius bundle twist (orientation reversal) + level-set as transverse wall/eps-band boundary.
- Numerical differential geometry from first principles: K=(LN-M^2)/(EG-F^2) via central finite differences of the two fundamental forms (no symbolic dependency).

**Algorithms**

- **Level-set / zero-curve tracing (formalization a) — repo's current method** — Extract the Central Finite Curve as R^{-1}(0) on the Mobius (u,v) domain. For each sampled u, treat R(u,.) as a 1-D function of v, detect sign changes on a v-grid, refine each bracket to a root, then lift (u,v*) to 3-D via the Mobius surface map. General 2-D fields use marching squares over grid cells instead of per-column scans.
  - _Method:_ Uniform sampling in v (e.g. 200 samples on [-0.5,0.5]) to bracket sign changes + bisection to tol~1e-9 (curve.py bisect/find_roots_in_v). Fundamental forms and K via central finite differences with step h=1e-5 (geometry.partials). For general fields: marching squares with linear edge interpolation x*=x0+(x1-x0)f0/(f0-f1).
  - _Pitfalls:_ Non-regular values (grad S=0 at a crossing) give singular/self-intersecting level sets and marching-squares saddle ambiguity — resolve with the asymptotic decider and perturb the threshold off critical values (Sard). Missed roots when the v-grid is coarser than the sign-change spacing (tangential/double roots where R just touches 0 are invisible to sign scans). Central-difference K near the v-boundary can lose the strict K<0 guarantee — restrict curvature-based zero claims to the open interior. Finite-difference step h too small amplifies round-off; too large adds truncation bias (classic O(h^2) truncation vs O(eps/h^2) rounding trade-off). Only a 1-D curve because M is 2-D; higher-dim S gives a wall, not a curve.
- **Ridge tracing via SCMS (formalization b) — recommended core** — Trace the intrinsic 1-D Rickness ridge in arbitrary ambient dimension: iterate points onto the set where the gradient is parallel to the top Hessian eigenvector and transverse curvature is negative, yielding the genuine 1-D 'Rick-maximal spine'.
  - _Method:_ Compute grad R and Hess R (analytic if available, else central differences on a Gaussian-smoothed field), eigendecompose H (Jacobi rotation for small dims — pure stdlib), form transverse subspace V from the smallest n-1 eigenvalues, update x <- x + V V^T m(x) until ||V V^T grad|| < tol. Connect converged points into a polyline by nearest-neighbor continuation; measure arc length by trapezoid/Simpson.
  - _Pitfalls:_ Second-derivative (Hessian) estimation is noise-amplifying — needs a smoothing bandwidth h with a bias-variance trade-off (too small: noisy ridge; too large: over-smoothed, merged ridges). Eigenvector sign/order flips when eigenvalues cross (umbilic points lambda_2=lambda_3) — track continuity and align signs to the previous step. Ridge bifurcations/terminations need branch handling. Only linear convergence; near-flat ridges stall. Literal argmax is 0-D (Morse) — do NOT sell the ridge as 'the set of maxima'; it is the crest, an honest but distinct object.
- **Predictor-corrector ridge/level continuation** — March along the curve (ridge or level set) by predicting a tangent step then correcting back onto the defining equation, giving an ordered, arc-length-parameterized 1-D curve rather than a scattered point cloud.
  - _Method:_ Predictor: step delta along the curve tangent (null space of the constraint Jacobian; for a level set, tangent perpendicular to grad S). Corrector: Newton iterations projecting back to S=0 (or to the ridge conditions). Adaptive step delta from local curvature. Detect loop closure when returning within delta of the start.
  - _Pitfalls:_ Step too large jumps between disconnected branches or across saddles; too small is slow. Newton corrector diverges near singular Jacobian (grad S=0) — fall back to bisection/trust region. Closed loops need robust termination to avoid infinite marching or premature stop; turning points where the tangent aligns with the march axis require pseudo-arclength continuation (Keller) rather than natural parameterization.
- **Mobius bundle / orientation-holonomy construction (formalization c)** — Endow the traced loop with the non-orientable Rickness-sign bundle: build the Mobius band as the mapping torus of a reflection over the core circle and verify orientation reversal by transporting a frame once around.
  - _Method:_ Parameterize core gamma(u) and a transverse director d(u)=(cos(u/2), sin(u/2)) with the half-angle giving period 4pi. Parallel-transport an orthonormal frame around u in [0,2pi] (small-step rotation integration) and compute the net frame determinant; assert det=-1 (reflection) => w_1!=0. Sample the band r(u,v) for rendering.
  - _Pitfalls:_ Using full-angle u instead of half-angle u/2 destroys the half-twist and silently yields an orientable annulus (w_1=0) — the non-orientability must be verified numerically, not assumed. Frame transport accumulates rotational drift; renormalize each step. The orientation-reversing physics is an ADDED postulate (a global symmetry S -> -S around the loop), not derived from canon — flag it as a modeling assumption, not a theorem.
- **Torus cross-check (closed-form zero circles)** — Sanity baseline where the zero set is analytically known: the torus Gaussian curvature K(theta) changes sign, so its zero set is the two circles theta=pi/2 and theta=3pi/2, giving a ground-truth to validate the numerical tracer.
  - _Method:_ Evaluate the closed-form K(theta), scan theta in [0,2pi) for sign changes, refine with bisection; compare recovered roots to the exact pi/2, 3pi/2 (repo torus.py / trace_torus_zero_circles).
  - _Pitfalls:_ The torus zeros are two DISJOINT circles — a tracer that assumes a single connected component will merge or drop one. Near theta=pi/2 the crossing is transverse (safe), but validating against it does not certify the Mobius tracer where roots can be tangential; use it as a necessary, not sufficient, check.

- Ports-and-adapters separation: a pure, deterministic, stdlib-only math core (core/) with I/O, CLI, RNG, and visualization as thin adapters that depend on the core and never vice versa
- Pure functions as the testable/doctestable unit: no side effects, no global state, exact or tolerance-pinned outputs
- Optional-dependency guarding: single-point try/except ImportError capability flags (HAS_NUMPY/HAS_MPL) with pure-stdlib fallbacks (ASCII renderer, Kahan/fsum) so the package imports and runs on a bare interpreter
- Reproducibility contract: exact arithmetic via fractions.Fraction where it matters, injected seeded random.Random (MT19937) everywhere, sorted iteration to defeat PYTHONHASHSEED, pinned seed+N for Monte-Carlo
- Testing architecture: tests/ mirroring the package, doctest-modules for executable formula docstrings, property tests for invariants, a dedicated reproduction test that pins analytic targets, 80% coverage gate
- Exact vs approximate assertion discipline: == for Fraction/int targets, math.isclose (PEP 485) with an explicit abs_tol for floats and near-zero comparisons
- argparse subcommand CLI as a thin translation layer: parse -> call one core function -> format, with main(argv=None)->int for testability
- Always-on ASCII visualization plus optional guarded PNG, so plots never become a hard dependency and the default renderer is golden-string testable
- Documentation split: README (quickstart/example) + ARCHITECTURE (module responsibilities, dependency direction, reproducibility and optional-dep policies)
- __init__.py as a thin public-API surface: __version__, __all__, curated re-exports from core rather than logic
- Grounding the math in source: Gojo's Infinity as a convergent geometric series (Sabiq essay, Zeno lens) and the Central Finite Curve as a constraint-manifold ridge (Rick and Morty), each implemented as a pure core computation

**Algorithms**

- **Pure-core exact series evaluation (fractions.Fraction)** — The math core (e.g. gojo zeno.partial_sum / geometric_sum) computes S_n = 1 - r^n and S_inf = a/(1-r) using fractions.Fraction so the reproduced target is EXACT, not float-approximate. This is the canonical 'pure function' unit: no I/O, no RNG, no global state, deterministic, and directly doctestable. It is what the CLI, ASCII viz, and tests all call; adapters never re-implement the math.
  - _Method:_ Exact rational arithmetic via fractions.Fraction. Closed form a/(1-Fraction(1)-r) for the infinite sum; iterated ratio**n for partial sums. No epsilon needed because equality is exact (Fraction(1,2) case gives exactly 1). Where the input is irrational (a measured float ratio) fall back to float and pin with math.isclose instead.
  - _Pitfalls:_ Fraction denominator grows without bound: ratio**n for symbolic n has O(n)-digit numerator/denominator, so gcd-normalization cost is quadratic and memory blows up for large n — cap n or switch to float past a threshold. Fraction rejects float construction that isn't exactly representable (Fraction(0.1) != Fraction(1,10)); take str or numerator/denominator at the boundary. Mixing Fraction and float in one expression silently coerces to float, destroying exactness — keep the core pure-rational and convert only at the adapter edge.
- **Kahan compensated summation (stdlib numeric fallback)** — When numpy is absent (as in this environment), reductions like field/heatmap means and L2 penalties in rickness.py must sum many floats in pure Python without accumulating O(n)*eps error. numerics.kahan_sum is the stdlib fallback the _optional dispatcher selects when HAS_NUMPY is False; math.fsum is the even-safer stdlib option for a flat list.
  - _Method:_ Maintain running sum s and compensation c. For each x: y = x - c; t = s + y; c = (t - s) - y; s = t. Error bound is O(1)*u regardless of n, versus naive summation's O(n)*u worst case (u = 2^-53). Python's math.fsum gives a correctly-rounded result and should be preferred for a single flat sequence; hand-rolled Kahan is for streaming/online accumulation.
  - _Pitfalls:_ A naive refactor that 'simplifies' s = s + x throws away the compensation term and reintroduces O(n) error — guard with a property test on a pathological input like [1e16, 1.0, -1e16]. Kahan does NOT help with catastrophic cancellation of nearly-equal large operands (subtract-then-sum), only with accumulation drift. Do not run Kahan on Fraction values — it is float-specific and pointless on exact rationals.
- **Seeded reproducible PRNG stream with deterministic sub-streams** — rng.py wraps random.Random(seed) (Mersenne Twister) so every stochastic draw — Monte-Carlo integration of the Infinity residual, multiverse sampling in central-finite-curve — is byte-for-byte reproducible from config.SEED. spawn(tag) derives independent child streams deterministically so parallel/nested sampling stays reproducible without a shared global.
  - _Method:_ random.Random is Mersenne-Twister MT19937, period 2^19937 - 1, seeded deterministically. Child streams: seed_child = parent.randint(0, 2^31-1) ^ tag, then Random(seed_child). For reproducible Monte-Carlo estimates, error scales as sigma/sqrt(N) (standard error), so pin the seed AND the sample count N in tests and assert the estimate against the analytic target with an abs_tol of a few standard errors.
  - _Pitfalls:_ Using module-level random.* (global state) makes runs order-dependent and non-reproducible — always inject a Random instance. PYTHONHASHSEED randomizes set/dict-of-object iteration order; if you iterate a set to feed the RNG the stream changes run-to-run even with a fixed seed — sort before iterating or never derive draws from set order. spawn via XOR can collide (two (parent,tag) pairs mapping to the same child seed); prefer hashing (seed, tag) through a wide mixer if many children. MT is NOT cryptographically secure — fine for simulation, never for secrets.
- **Numeric-target regression assertion (math.isclose)** — Tests assert that the code reproduces known analytic targets: geometric_sum(1/2,1/2)==1 exactly (Fraction, use ==), Mobius centerline Gaussian curvature K(u,0)==-1/4 (float, use isclose), Monte-Carlo estimates within tolerance. This 'pin the reproduced number' pattern is the backbone of a rigorous math project's test suite.
  - _Method:_ math.isclose(a, b, rel_tol=1e-9, abs_tol=0.0) implements |a-b| <= max(rel_tol*max(|a|,|b|), abs_tol) (PEP 485). Use exact == for Fraction/int targets. For values near zero the relative term collapses to 0, so an explicit abs_tol is mandatory. For Monte-Carlo, set abs_tol ~ k*sigma/sqrt(N).
  - _Pitfalls:_ Default abs_tol=0.0 means isclose(x, 0.0) is True only for exactly 0.0 — comparing a residual against zero silently requires an abs_tol you must supply. Comparing Fraction to float coerces to float and can fail an == you expected to pass; keep exact targets exact. Over-tight rel_tol on numerically-differentiated curvature (finite differences) causes flaky tests because the discretization error dominates roundoff — size the tolerance to the step-size truncation error O(h^2), not to machine epsilon.
- **Optional-dependency capability dispatch (import guard)** — _optional.py attempts to import numpy/matplotlib once, exposing boolean capability flags (HAS_NUMPY, HAS_MPL). viz/png.py and any accelerated numeric path query these flags and fall back to the stdlib implementation (ASCII renderer, kahan_sum) when the optional dep is missing, so the package imports and the CLI runs on a bare interpreter.
  - _Method:_ try: import numpy as np; HAS_NUMPY=True; except ImportError: np=None; HAS_NUMPY=False. Same for matplotlib, with matplotlib.use('Agg') set BEFORE importing pyplot so PNG rendering works headless. Public functions branch on the flag; both branches must return the same numeric result to within tolerance (assert this with a cross-check test that runs only when the dep is installed).
  - _Pitfalls:_ Bare `except:` swallows real errors (a corrupt numpy install) as 'absent' — catch ImportError specifically. Importing matplotlib.pyplot before selecting the Agg backend can fail on headless CI or pop a GUI. Silent numeric divergence between the numpy and stdlib paths is the dangerous failure: a fast float32 numpy path vs float64 stdlib path can disagree past your test tolerance — pin both to float64 and cross-validate. Do NOT let core/ import numpy at module top level; the core must stay pure-stdlib and import-safe, with acceleration confined to adapter modules.
- **ASCII heatmap rendering with normalization (always-on visualization)** — viz/ascii.py maps a 2-D scalar field (curvature over the Mobius (u,v) grid, rickness over a multiverse slice) to a character ramp, giving a dependency-free visualization that is testable by exact string comparison. This is the default renderer; PNG via matplotlib is the optional enhancement.
  - _Method:_ Normalize v_norm = (v - vmin)/(vmax - vmin) with a guard for vmax==vmin (constant field -> map all to the ramp midpoint). Index the ramp ' .:-=+*#%@' as ramp[round(v_norm*(len(ramp)-1))]. Correct for terminal cell aspect ratio (~2:1 height:width) by sampling twice as many columns as rows, or by duplicating columns, so a circle reads as a circle.
  - _Pitfalls:_ Division by zero when the field is constant (vmax==vmin) — must special-case. Ignoring the 2:1 character aspect ratio makes isotropic fields look squashed. Off-by-one on the ramp index when v_norm==1.0 rounds to len(ramp) (out of range) unless you index with len-1. Locale/encoding: stick to ASCII (or explicitly encode UTF-8) so the golden-string test is stable across platforms. NaN/inf in the field (e.g. curvature at a degenerate point) must be clamped or rendered as a sentinel char, not passed to round().
- **argparse subcommand dispatch (thin CLI adapter)** — cli.py builds one ArgumentParser with add_subparsers(); each subcommand (e.g. `zeno`, `series`, `curvature`, `render`, `sample`) parses its own args, calls exactly one pure-core function, and formats the result. The CLI holds no math and no persistent state — it is a translation layer between argv and the core, which keeps the core independently testable and the CLI trivially mockable.
  - _Method:_ Not numeric: sub.set_defaults(func=handler) then args.func(args) dispatch. main(argv=None) takes argv for testability (pass a list in tests instead of touching sys.argv). Return an int exit code; reserve 0 for success, 2 for usage errors (argparse default), 1 for computation/domain errors surfaced as clean messages.
  - _Pitfalls:_ Fat CLIs that embed the math can't be unit-tested without spawning a subprocess and can't be reused as a library — keep handlers to parse -> call core -> print. Reading sys.argv directly instead of accepting argv makes CLI tests brittle. Letting a core ValueError (e.g. ratio>=1) escape as a traceback leaks internals; catch domain errors at the CLI boundary and print a one-line message with a nonzero exit. Global mutable config touched by subcommands reintroduces order-dependence — pass parsed args explicitly.
