infinite-hotel-scheduler

Hilbert’s Infinite Hotel as a cloud scheduler — a resource allocator that is never full, using countable re-indexing to accommodate any number of new arrivals.

source ↗ All projects

The idea

Hilbert’s Infinite Hotel has countably infinitely many rooms, all occupied. Yet it can always accommodate a new guest: shift every guest from room n to room n+1, freeing room 1. For a countably infinite coach of new guests: shift existing guests from room n to room 2n, freeing all odd-numbered rooms.

This package models a cloud scheduler as the Infinite Hotel. Worker slots are numbered by natural numbers. When all slots appear full, the scheduler re-indexes to create a vacancy. In practice the “infinite” capacity is bounded by available RAM — the code explicitly models the limit and refuses to re-index past it, so it behaves correctly in finite memory while demonstrating the paradox for smaller inputs.

The mathematics

Hilbert re-indexing 
Single arrival: move guest n → room (n+1)  for all n
  Room 1 freed. O(N) shift.

Countably infinite arrivals: move guest n → room (2n)
  All odd rooms freed. O(N) re-index.

Countably many coaches of countably many guests:
  Cantor pairing: room (coach, seat) → room 2^coach × 3^seat
  (unique prime factorisation guarantees injectivity)

Practical limit: scheduler enforces a MAX_SLOTS cap beyond which
  re-indexing is refused and a real "hotel full" error is raised.
